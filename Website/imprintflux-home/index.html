系统分析 / 原型探索

Workspot：把行为组织成可复用的内容

我关注 NPC 在场景中如何进入位置、执行动作、响应打断，以及这些行为如何被任务系统调用。研究的重点是内容组织和制作方式，而不只是单个动画效果。

  • 拆解 Entry 组合、行为序列与生命周期。
  • 对照 UE SmartObject，思考交互入口与行为执行的分工。
  • 将分析转成工具需求、编辑方式和最小验证方案。
展开我的研究思路 ＋

一个可复用的行为单元需要说明：谁可以使用、如何进入、运行时谁持有控制权、何时退出。工具则需要让创作者看见这些关系，而不是只把底层字段堆在属性面板里。

这部分材料是对既有系统的研究与 UE 适配探索，和下方自研插件的实现说明分别呈现。

架构研究 / 设计分析

从场景编辑到叙事执行

围绕 InteractiveScene、SceneGraph 和 ExecutionStream，梳理作者看到的图形编辑结构与运行时执行过程之间的关系。

  • 区分流程关系、时间安排与具体行为资源。
  • 关注并行、等待、汇合、取消与打断。
  • 把分析沉淀为需求说明和工具设计方案。
展开我的设计关注 ＋

创作者需要表达“谁先做什么”和“什么时候等待”，执行层则必须处理依赖、完成条件和中断。我的思考是让编辑视图服务理解，让执行模型负责可靠调度，两者通过清晰的数据契约连接。

EXPLORING / AI NARRATIVE

从自然语言意图，到可检查的时序编排

我正在探索让创作者先表达意图，再由系统组织 Speak、MoveTo、Wait、Signal 等最小单元。图结构可以成为编排结果的检查与修改视图，而不是唯一输入入口。

当前为方案与研究方向，关注执行约束、人工修订和调试可见性。

03 / IMPLEMENTATION NOTES

开发笔记Engineering notes

架构价值体现在具体路径里：
谁拥有数据，何时提交，失败如何结束。

01让一次点击携带可靠的实体身份+

控件点击不携带长期缓存的实体快照。PresentationManager 从当前绑定反查实体，并核对实际 Widget、实体句柄和池租约代数；验证通过后派发 OnEntityActivated。

Widget → PresentationManager → PointActor → 共享 ViewModel / Focus

业务宿主读取当前数据；Focus 分支在设备通知后再次核对宿主与实体，避免蓝图回调切换楼层或资产后继续执行旧请求。派发成功与实际移动到达是两种结果。

02把 USD 适配留在外部，把提交契约留在核心+

FormUSD 读取 USD 并构造候选数据，通过 FormScribeEditor 的 ApplyAssetDataBatch 校验和提交。核心公开的是通用批量数据接口与导入来源槽位，无需识别 USD 插件。

USD Reader → 候选数据 → 完整校验 → 编辑器事务 → 数据通知

导入和重导为实体生成全新 UE InstanceId；保留适用的 UE 定义与模型配置，但不把源 GUID 当成持久身份复用。导出失败可能留下资源文件，当前不保证整个目录事务回滚。

03把消息暂存和实体状态分开+

JHPlatform 的世界消息 Hub 接收已解析告警，按楼层匹配注册的 PointActor。未交付消息按楼层和设备保留最新值，晚注册时尝试补投，成功后按序号删除对应消息。

已解析告警 → MessageHub → 楼层宿主 → EntityManager → 表现反馈

Hub 的暂存表不是已交付告警的状态缓存。实体状态仍由核心管理；业务指定设备匹配字段，不把后端记录身份与设备码混作一个概念。

04共享材质身份，显式表达转换限制+

FormUSD 为 Parts 与 Items 构建同一份材质清单，按 UE 完整材质身份去重，输出共享库与相对引用，同时检查模型材质槽、面分区和绑定关系。

MaterialInventory → Materials.usda + .mtlx → 模型槽位 → 场景实例

当前 MaterialX 转换覆盖常量 Default Lit Standard Surface 范围，不包含完整贴图与烘焙。不支持的材质保留身份、用途和诊断；不把结构可读等同于外观还原。
